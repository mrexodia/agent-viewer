# Agent Session Viewer - Implementation Roadmap

## Quick Start

You are implementing a real-time session viewer for agent workflows that write JSONL event logs.

**Core Documents:**
- `DESIGN.md` - Complete system architecture and specifications
- `TESTS_MVP.md` - Comprehensive test suite for MVP phase

## MVP Deliverables

Build these three components:

### 1. Watcher (Go)
**Purpose**: Monitor local .jsonl files and stream updates to server  
**Location**: `watcher/main.go`  
**Key Features**:
- Recursive directory scanning
- File change detection (fsnotify)
- Line-by-line reading
- 100ms batching
- WebSocket client with reconnection

**Dependencies**:
```go
require (
    github.com/fsnotify/fsnotify v1.7.0
    github.com/gorilla/websocket v1.5.1
)
```

### 2. Server (Go)
**Purpose**: Receive updates from watchers and serve web UI  
**Location**: `server/main.go`  
**Key Features**:
- WebSocket server (for watchers)
- HTTP server (for browsers)
- In-memory session storage
- REST API
- Server-Sent Events (for live updates)

**Dependencies**:
```go
require (
    github.com/gorilla/websocket v1.5.1
)
```

**API Endpoints**:
- `ws://localhost:8080/watch` - WebSocket for watcher
- `GET /` - Serve web UI
- `GET /api/sessions` - List sessions
- `GET /api/sessions/{path}` - Get session content
- `GET /api/sessions/{path}/stream` - SSE for live updates

### 3. Web UI (HTML/JS)
**Purpose**: Display sessions and live updates in browser  
**Location**: `server/static/index.html`  
**Key Features**:
- Session list with live indicators
- Session viewer with line numbers
- Auto-scroll with manual override
- SSE connection with auto-reconnect

## Critical Implementation Notes

### Message Format

**Watcher → Server**:
```json
{
  "type": "line",
  "path": "2026-01-04.jsonl",
  "line": "{\"event\":\"start\"}\n"
}
```
⚠️ **Include the newline character** - it's part of the line

**Server → Browser (SSE)**:
```
event: line
data: {"path":"2026-01-04.jsonl","line":"{\"event\":\"start\"}","line_num":1}

```

### File Reading Strategy

```go
// Track position per file
type FileState struct {
    Path     string
    LastLine int
    LastSize int64
}

// On file modify:
file.Seek(lastSize, 0)  // Seek to last position
scanner := bufio.NewScanner(file)
for scanner.Scan() {
    sendLine(scanner.Text() + "\n")  // Include newline!
}
```

### Batching Implementation

```go
// Collect lines for 100ms before sending
ticker := time.NewTicker(100 * time.Millisecond)
batch := []LineMessage{}

for {
    select {
    case line := <-lineQueue:
        batch = append(batch, line)
    case <-ticker.C:
        if len(batch) > 0 {
            sendBatch(batch)
            batch = batch[:0]  // Clear
        }
    }
}
```

### SSE Broadcasting

```go
// Track SSE clients per session
type SSEClients struct {
    clients map[string][]chan LineEvent  // path -> clients
    mu      sync.RWMutex
}

// When line received:
func (s *SSEClients) Broadcast(path string, event LineEvent) {
    s.mu.RLock()
    defer s.mu.RUnlock()
    
    for _, client := range s.clients[path] {
        select {
        case client <- event:
        default:
            // Client slow, skip
        }
    }
}
```

| Metric | Target | Measurement |
|--------|--------|-------------|
| File → Browser latency | <500ms | Timestamp in JSON, log in browser |
| Batch interval | 100ms | Time between fsnotify and send |
| Reconnect time | <30s | Time from disconnect to connected |

| Concurrent viewers | 10 | Open 10 browser tabs |

## Common Pitfalls

❌ **Don't** use JSON marshaling for lines - just send raw string  
✅ **Do** preserve exact line content including `\n`

❌ **Don't** use HTTP long-polling for live updates  
✅ **Do** use Server-Sent Events (one-way is sufficient)

❌ **Don't** try to parse JSONL in watcher/server  
✅ **Do** treat lines as opaque strings (parsing is future work)

❌ **Don't** use database for MVP  
✅ **Do** use in-memory map (data loss on restart is acceptable)

❌ **Don't** implement complex sync protocol yet  
✅ **Do** just send all lines on startup (simple is fine for MVP)
